# H4 Fresh Review — PASS

**Scope:** Independent, read-only review of the storage-policy diff, focused tests, H4-A/H4-B, and saved before/after profiles. No source or test files were changed; no tests, Gate 0, Finder, Wine, or replay were run.

## Findings

- **Root cause and fix match.** The old predicate scanned all 132 exclusions for every regular-file path and repeatedly traversed `Path.parents`. H4-A recorded 92,020,702 yielded ancestors and 492.596 seconds in consumer work; in `ATen/ops`, 7,235 files took 85.612 seconds of accounting while enumeration took 0.022 seconds. The new code builds a set from the same absolute exclusions once and checks the candidate plus each ancestor once (`storage_policy.py:481-490,3111-3112,3190-3192`). This is the minimal lookup change and preserves exact-path and excluded-ancestor matching.
- **Accounting and traversal behavior are preserved.** The inode allocation map, “any non-excluded hardlink keeps the inode included” rule, pathname-based logical/file counts, and total/excluded allocation sums are unchanged. No roots or directories are pruned; `.git` remains included. Root `lstat`/identity checks, non-following `os.walk`, symlink and cross-device child pruning, and regular-file-only accounting are untouched (`storage_policy.py:3125-3189`). The existing path-based walk still has its previously documented check/use and descendant-error limitations; this patch does not address or worsen them.
- **Focused regression coverage is relevant.** The new tests bound set-membership checks by path depth and cover exact and ancestor exclusions; the nested-root test checks `.git` inclusion, pathname counting, and inode allocation deduplication (`test_storage_policy.py:141-189`). Existing tests cover hardlinks through excluded trees, signed-output accounting, thresholds, PrefixLease and historical closure; recovery tests cover symlink-root rejection. The supplied focused-run record reports 50 passing tests across the five named suites; I did not rerun them.
- **Before/after evidence supports the optimization.** The saved profiles show the same 11 roots and 132 exclusions. The exact-shape old-code profile took 493.824669 seconds; the fixed-code profile took 5.007292 seconds, about **98.6× faster** under the same profiler. Regular paths/inode keys/included keys changed from 53,033/51,888/50,826 to 53,034/51,889/50,827. Logical bytes rose by 18,299; allocated bytes fell by 892,928; excluded allocation rose by 28,672. Given the one-path count change and live workspace/cache scan, this small aggregate delta is plausibly ordinary churn and does not indicate intentional scope pruning. The profiles do not identify per-file changes, so churn is plausible, not proven.

## Limitation

The separately reported operational call exceeded one hour and was interrupted; it is not a completed baseline. The 493.824669-second comparison is the completed, instrumented old-implementation profile, and the 98.6× ratio applies to these two profiled calls only.
