# Z9R-H1-D — Security and fail-closed model

## Decision

**NO-GO to closing Z9 or admitting a new Gate 0 with the current source.** The repository has no run-level terminal-closure schema or verifier. Gate 0 currently rejects signed outputs that exceed their original persistent reservation, and there is no safe exception path that distinguishes a terminal historical failure from a live/reusable run. A separate, append-only, per-run closure record is architecture-compatible, but implementation and independent review are prerequisites.

The intended narrow exception is: recognize the exact already-failed run as a terminal historical record for output-reservation accounting, while keeping its original manifest, original Gate POST `BLOCKED` result, R5/T8 classification, cleanup receipt, and all tree bytes unchanged. The closure must never make the run reusable or grant a new storage allowance. If any required historical anchor is unavailable or inconsistent, keep Gate 0 blocked.

## Source findings that constrain the design

* The signed storage-manifest schema lists admission, runner, and storage fields but no `terminal`, `closed`, or `retired` state (`experiments/storage/storage_policy.py:63-79`). `_signed_persistent_output_snapshot()` scans every `.json` manifest in the canonical manifest directory, validates its signed identity, measures its output, and emits `signed experiment output exceeds its persistent reservation` when measured allocation exceeds the original signed `estimated_persistent_bytes` (`storage_policy.py:574-693`). The Z9 manifest remains an `ALLOW` storage-admission manifest with a 314,572,800-byte persistent reservation; that value must remain fixed.
* The current output-tree fingerprint is not a content digest: `_persistent_output_snapshot()` hashes relative path and stat identity fields (device, inode, mode, owner, link count, size, times, and allocation), but not each file's bytes (`storage_policy.py:464-534`). It returns an empty-tree measurement when the root path is missing (`:472-476`) and records symlinks rather than rejecting them (`:497-519`). A closure verifier must explicitly reject a missing expected tree, missing required artifact, unexpected symlink, or other special file.
* The signed-output scanner silently skips some malformed, unsigned, noncanonical, or invalid manifest candidates (`storage_policy.py:609-645`). A closure record for the target run must not be silently skipped when its manifest or certificate fails validation: a missing or invalid target manifest/certificate is a blocker. The scanner must first bind the closure's exact run ID to the canonical manifest path and then fail closed on any mismatch.
* Existing Gate 0 compares historical output bindings with its signed baseline and takes a second measurement to detect changes during accounting (`storage_policy.py:1969-1981, 2052-2060`; `storage_gate0.py:114-200`). Those bindings include an output tree digest, but that digest currently contains metadata rather than file-content hashes. The current project total remains computed over all project files; `exclude_paths` changes only the unrelated-growth subtotal (`storage_policy.py:2106-2206`). A valid closure may participate in that comparison only if every subsequent Gate pass rechecks the exact closure snapshot. Its output tree and manifest must remain in the total used for the 55 GiB ceiling.
* PrefixLease startup requires a valid signed `ALLOW` manifest and that manifest's Gate 0 attestation hash to equal the *current* attestation hash (`storage_policy.py:4940-4984`). NativeRunLease applies the same current-attestation binding (`:7050-7085`). This is useful protection, but closure acceptance must be implemented only in historical accounting; the closure artifact must never become a lease manifest or runner authorization.
* `_active_lease_markers()` treats any surviving `.json` marker as active/interrupted and fails closed if its directory cannot be opened (`storage_policy.py:2404-2423`). Build retention exposes active, failed/retiring, completed-pending-retirement, and unknown states (`experiments/storage/build_retention.py:3507-3537`). Its `_require_no_live_process()` uses `lsof +D`, but it is currently scoped to build-root retirement/adoption, not the Z9 output/prefix (`build_retention.py:6064-6071`). No single existing helper proves that no process still uses this run's prefix and output.
* The per-user signing key is checked for no-follow open, ownership, mode `0600`, and one link; HMACs detect edited records under the existing local trust model (`storage_policy.py:1052-1103, 1180-1209`). Because the key is owned by the same user who owns the workspace, this HMAC is not an independent defense against a malicious process running as that user. Treat it as tamper evidence for the repository's current trust model; do not claim protection against a compromised same-user account. If that stronger attacker is in scope, closure needs an independently held signing key or external review signature.

For Z9 specifically, the original failure is recorded in `runs/step11d3b-baseline-01-20261014-130823-44892b9b/run-result.json`: its `gate0_post` is `BLOCKED`, its run result is `FAIL`, and its blockers include the signed-output overrun. The reported 598,573,056-byte POST tree amount is a preserved reconstruction, not a numeric field in that `gate0_post` object; bind the closure to the exact result and report evidence and preserve that distinction. The provenance review's current tree inventory digest `2ed704d0ce598c9cebf4028e9a342cbe174b7427c43aa34bd0253e7c7dbec850` is a useful measured snapshot, but the review itself states it is not an existing closure certificate or a continuous monitor (`Z9R-H1-A-PROVENANCE.md:114-147`). It does not establish that no artifact was changed before the snapshot.

## Required closure contract

Store one canonical closure file per run in a dedicated closure directory outside the signed run tree, so that the certificate does not make its own tree digest recursive. Create it once with exclusive creation and durable directory sync; never overwrite it. Require one canonical entry for the exact ID, with no duplicate or ambiguous records. Gate 0 must reject symlinked, multiply linked, non-regular, malformed, unauthenticated, or unexpected closure files.

The record should bind at least:

* schema and closure-policy version; exact experiment/run ID; experiment token; canonical storage-manifest path, raw SHA-256, HMAC validity, and unchanged original reservation;
* exact output-root path plus pinned root and parent device/inode identities; complete sorted relative-path inventory; each entry's kind, mode, device/inode, link count, logical size, allocated blocks, and SHA-256 for every regular file; current allocated-byte total and inventory digest;
* the original run-manifest, `run-result.json`, PrefixLease cleanup receipt, Gate POST status and blocker list, and R5/T8 classification evidence hashes; explicitly preserve the numeric POST allocation's report-reconstruction provenance;
* positive terminal evidence; no live process using the run output or prefix; no active/interrupted PrefixLease; no active, pending, failed, or ambiguous BuildLease state; verified cleanup state; and the measurement/tool source hashes;
* literal semantics such as `historical_failure_preserved=true`, `authorizes_execution=false`, `changes_original_gate_result=false`, and `counts_toward_project_scope=true`.

The closure code must check all correlated IDs, paths, hashes, and statuses against the source records, not merely repeat values supplied to the closure command. For Z9, that includes the separate storage manifest and `run-manifest.json`; the prefix-cleanup receipt's manifest SHA refers to the storage manifest, not the run manifest. The original manifest must pass its HMAC and schema validation and match a previously evidenced original hash. The signed reservation remains exactly 314,572,800 bytes. The future-run reservation of 4,974,444,544 bytes must not enter the old manifest or closure arithmetic.

For the historical result, require a terminal `run-result.json`, the exact existing `gate0_post.status=BLOCKED` and ordered blockers, `run-result.status=FAIL`, and the existing R5/T8 evidence. Verify the cleanup receipt's signature, run ID, manifest binding, terminal cleanup state, and active-marker removal. Check original result and cleanup files before and after measurement. Do not infer Gate POST PASS from PrefixLease cleanup PASS. A missing historical failure record, unexplained blocker rewrite, missing required artifact, or inconsistent classification is a blocker.

Before and after closure creation, hold the storage-certification and shared storage-allocation locks using the repository's established lock order. Require no active PrefixLease marker and no active/ambiguous BuildLease state. Check the recorded Wine/controller PID with process identity that avoids PID-reuse confusion, and use a no-match process scan for both output root and prefix; inability to run the scan or any matching process must block. The existing `lsof +D` helper is a pattern, not a complete closure guard: it is path-based, is not currently invoked for run outputs, and does not pin the path it inspected.

Measure through pinned directory descriptors. Open every path component without following symlinks; pin and verify repository, output root, and parent identities; reject path escape, device changes, symlinks (including ancestor substitution), hard-link aliases that permit out-of-tree writes unless explicitly accounted for, and non-regular nodes. Hash file contents from descriptors, compare descriptor metadata before/after reads, enumerate sorted relative paths, and revalidate names/identities after the walk. Take two complete inventories and require byte-for-byte equality of the canonical inventory, root identity, and allocation total before publishing the certificate. Write the certificate outside the run tree with exclusive/no-follow creation and `fsync`; reopen and verify it, then remeasure the tree and lease/process state before declaring closure complete. A race, permission error, disappearance, changed directory listing, changed inode, changed byte hash, or incomplete scan is a hard failure.

The tree hash protects against later additions, edits, removals, and substitutions only after it is established. To claim that an artifact was not tampered with before closure, compare it to an earlier trusted per-artifact digest (for example, an immutable run-manifest/index/result hash or the exact original Gate POST evidence). If no earlier hash exists, label the closure as a snapshot of the surviving bytes and do not claim pre-closure historical integrity for that artifact. Z9's current review inventory is post-run and does not by itself supply a Gate POST content baseline.

## Attack scenarios and required outcome

| Scenario | Required fail-closed behavior |
|---|---|
| Wrong run ID or stale manifest | Reject unless certificate filename, certificate ID, experiment token, canonical manifest path, manifest ID, cleanup receipt ID, run-result ID, Gate POST evidence, and output-root path all agree. Re-read the exact original manifest bytes and compare the raw SHA and signature before and after the tree walk. A stale/changed/missing manifest blocks closure. |
| Tampered or missing artifact | Compare every current required path to any trusted historical content hash; reject hash mismatch and any missing required file. Reject missing output root instead of treating it as a zero-byte tree. If an artifact has no earlier trusted hash, do not assert that it is historically unchanged; a post-hoc closure snapshot cannot prove that. |
| Active run or second PrefixLease/BuildLease | Refuse closure if any active/interrupted PrefixLease marker exists, if any process has cwd/open files in the prefix/output, or if BuildLease state is active, pending, failed/retiring, or unknown. Recheck after inventory. The run's own old `decision=ALLOW` is not terminal proof. |
| Tree mutation during closure | Take complete content-hashed inventories before and after; compare names, types, identities, bytes, and allocated totals while locks are held. Any delta or failed scan aborts without writing a closure. Locks alone do not stop a writer that ignores them. |
| Copied certificate or wrong path | Accept only the single file at the canonical `closures/<run_id>.json` path; verify its internal run ID, manifest hash, output-root identity, and dedicated closure HMAC. Reject duplicates, hard links, and path/name disagreement. A certificate copied to another ID cannot satisfy that run's manifest binding. |
| Path/symlink substitution | Resolve identity from no-follow directory descriptors, not a path string alone. Reject symlinks in every ancestor and in the run tree, verify device/inode and ownership, and compare path-to-descriptor identity again before and after inventory. Any replacement or redirection blocks. |
| Future mutation after closure | On every Gate check recompute the full tree inventory and compare it to the closure snapshot. A new 64 MiB file, edited manifest/result, removed file, changed symlink, changed hard-link relationship, or changed tree root must block even if the 55 GiB project ceiling is still under limit. Preserve unrelated nonlease-growth checks. |
| Try to turn historical FAIL into PASS | Never edit the signed storage manifest, `run-result.json`, embedded Gate POST, cleanup receipt, controller result, or R5/T8 report statements. Bind their hashes/statuses; expose the closure only to the historical accounting branch. A new current Gate 0 PASS is a separate attestation and does not alter the historical Gate POST. |

## Accounting and authorization boundaries

The exception should alter only the predicate that currently rejects a measured tree because it is greater than its signed historical reservation. It must not rewrite that reservation, recategorize the old bytes as zero, or raise a general allowance. For a closed run, Gate 0 may accept the exact closure-time tree allocation as a known historical overrun only while the complete content/identity snapshot still matches. The output and manifest continue to contribute to `measure_project_usage()` and the conservative project total. The closure record itself also contributes to scoped project allocation; a new inventory and Gate 0 attestation must account for that new record.

Keep the usual current-state checks independent: current scoped bytes must remain at or below 55 GiB, projected free space at or above 50 GiB, and unrelated nonlease usage must still match its fresh baseline. The closure cannot offset future growth inside or outside its tree. Since the current scanner excludes a run tree from the nonlease comparison only after it becomes a valid binding, the closure binding must include the exact content digest and be reverified on every subsequent Gate pass. Add the closure-verifier source and tests to Gate 0's control-hash set so a verifier change invalidates the prior attestation.

Do not pass a closure path or certificate to `PrefixLease`, `NativeRunLease`, or a runner as an authorization object. Keep closure lookup local to historical storage accounting. Continue requiring a newly admitted manifest bound to the current Gate 0 attestation for any future run. The source's current-attestation binding already provides a useful barrier to reusing the old manifest after refresh, but tests must prove that closure data itself cannot satisfy any lease/runner admission path.

## Minimum adversarial regressions for this workstream

In addition to the broader F suite, test: the one original failed run closes only when all evidence and liveness guards pass; original storage-manifest bytes/hash/reservation stay unchanged; original result and embedded Gate POST remain byte-identical and `FAIL/BLOCKED`; R5/T8 remain unchanged; missing or edited manifest, result, cleanup receipt, or required tree entry fails; wrong ID/hash and copied certificate fail; a second/active lease or live process fails; mutation injected between either pair of tree walks fails; symlink substitution and root replacement fail; a changed file after closure fails at Gate 0; a new 64 MiB unrelated write still fails unrelated-growth checks; closure data cannot start a PrefixLease/NativeRunLease; and free-space/scope thresholds still block at their existing 50/55 GiB limits.

The repository already has useful tests that an over-reservation blocks and is not excluded (`experiments/storage/test_storage_policy.py:444-453`) and that changed historical output bindings fail Gate 0 (`experiments/storage/test_g0c_checks.py:191-209`). Those tests do not yet cover content-hashed terminal closure, copied certificates, liveness, pre/post tree races, missing artifacts, or authorization isolation.

## Scope and limits

This is a read-only source/design review. No code, historical run artifact, manifest, receipt, Gate result, inventory, or report was edited by this subagent, and no tests, process liveness scan, Gate command, or storage measurement was run. The only requested deliverable from this workstream is this report.
