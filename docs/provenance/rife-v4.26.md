## Runtime boundary

The native runtime accepts `MTLTexture` inputs, preprocesses them with Metal, runs the model through MPSGraph and purpose-built Metal kernels, and writes an `MTLTexture` output. Image data does not pass through `CGImage`, image files, CPU RGB buffers, CPU readback, Vulkan, or Python on the live path. Python/PyTorch is limited to conversion and the CPU/GPU reference runner used during validation.

The model is color-only. QUALITY and BALANCED remain internal Metal settings. The external capability contract continues to advertise `FRAMEGEN_CAP_COLOR_ONLY`; no RIFE model, timestep, or quality-tier fields are added to the generic host ABI.

## Runtime memory bound

The Metal implementation estimates its intermediate buffer set from the padded mod-64 pixel count before it compiles an MPSGraph plan. One request is limited to 1280 MiB of RIFE scratch buffers, and the reusable scratch pool is limited to 2 GiB total across at most three sets. The implementation rejects a larger request before graph compilation; an allocation failure below the cap is still reported if the device cannot provide the memory. The byte estimate counts 82 scalar values per padded pixel and excludes MPSGraph temporary workspaces, source/output textures, and optional HUD textures. At 1920x1080, the padded float32 QUALITY scratch set is approximately 653 MiB; three such sets are approximately 1.91 GiB. At 3840x2160, one padded QUALITY set exceeds the per-request limit and is rejected. These are buffer-shape calculations, not measured total device-memory use. The checked-in benchmark corpus is 128x72 and provides no full-resolution throughput or total-memory evidence.
