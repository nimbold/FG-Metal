# Step 11 closeout B — architecture and invariant audit

Audit scope: read-only review of accepted Step 11 reports and retained run evidence. No source code or tests were changed or run. The working tree had pre-existing BR9R/storage modifications; this audit did not touch them.

## Evidence boundary

The repository does not contain the frozen R5 DXVK source tree or its full build overlay (`adapters/dxvk/` contains only `.gitkeep`). R5 implementation claims below are therefore classified from the retained reports, run manifests, and ledgers, not from a fresh source checkout. The source-latency audit itself says it did not independently reproduce the source-tree digest or rehash the bridge/provider, and that the provider source was absent from its snapshot (`experiments/dxvk_macos_step11dR/evidence/source-latency-lifetime-audit.md`, “Candidate identity checked” and “Normal shutdown and final-job drain”).

## Readiness decision

The existing architecture proves the basic one-source Vulkan → Metal → Vulkan transport and preserves app-visible accounting. That is enough to begin the bounded 11E implementation work. It is **not yet safe to start or pass the real-resolution A/B runtime gate** under the exact requirements supplied: neither the app backbuffer selected per source frame nor cross-job A/B history ownership has been closed, and reset behavior needs evidence at the two-source boundary.

Minimum blockers before the real A/B run:

1. **Bind source snapshots to identities under `FLIP_SEQUENTIAL` with `BufferCount=2`.** Emit/validate the actual source image identity and AppFrameId for successive Presents. Require the selected source resources to be distinct/consecutive as expected; the current test explicitly has no rotation trace.
2. **Implement and audit cross-frame HISTORY lifetime.** Hold A unchanged until the Metal workload for B signals completion, keep B’s output separate, and reclaim every referenced resource exactly once. Existing R5 per-job paired-slot retirement does not prove this.
3. **Enforce and demonstrate reset pairing.** A and B must have matching swapchain/resource generation and valid consecutive source identities. Reset must clear retained history and prevent any old-generation or discontinuous pair from reaching Metal/Vulkan consume. Include a complete final job/slot release ledger, resolving the existing EOF-owned-slot ambiguity for the tested path.

Cadence instability, incomplete optional failure injection outside those paths, D3D9 interop parity, and BR9R/Finder causality do not independently block this transport gate. They must not be described as solved, but no further AppKit/Finder work is indicated by these architecture findings.

11E_READY = NO

Minimum blockers: source/backbuffer identity at two-buffer flip rotation; cross-frame A/B history lifetime; generation-reset stale-pair rejection plus complete bounded-release evidence.
